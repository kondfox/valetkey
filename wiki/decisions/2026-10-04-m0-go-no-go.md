# M0 go/no-go: the fence holds on macOS and Linux, with three design changes

Date: 2026-10-04 · Status: Active

## Context
The design relied on sandbox and client behaviour nobody had verified. The fail-closed rule
([[2026-10-04-fail-closed-fence-capabilities]]) required each capability to be confirmed per
platform before any product code, with a predefined consequence for every miss.

## Options considered
Per capability, the go/no-go table in `docs/design.md §11` fixed the outcomes in advance: confirm,
downgrade the platform to unfenced, count a source as exposed, or refuse a feature on a client.

## Decision
M0 ran on 2026-10-04 and the table is filled in (`docs/design.md §11`). Summary:

| Capability | macOS | Linux / WSL2 |
|---|---|---|
| Deny-read for child processes | ✅ | ✅ |
| Unix-socket connect deny | ✅ per path | ✅ all-or-nothing; `allowAllUnixSockets` → unfenced |
| Job submission blocked | ✅ | ✅ while unix sockets are denied |
| Keychain / Secret Service blocked | ❌ | ✅ |
| Raw IP / metadata blocked | ✅ with `allowedDomains` | ✅ with `allowedDomains` |
| Symlink-safe deny-write | ✅ via parent-dir deny | ✅ via parent-dir deny |
| Known write scope | ✅ | ✅ |
| localhost TCP per port | ❌ raw (with `allowLocalBinding`) | ✅ (network namespace) |
| Hook-capable agent config write-protected | ✅ | ✅ |
| MCP servers outside the sandbox | ✅ | ✅ |
| Elicitation can't be auto-accepted | ❌ | ❌ |

The misses lead to these changes:
- **Elicitation** ❌ → approval moves out of band: [[2026-10-04-out-of-band-write-approval]].
- **Keychain** ❌ on macOS → `keyring` is exposed there; protected local secrets use
  [[2026-10-04-local-secret-store]].
- **localhost TCP** ❌ on macOS with `allowLocalBinding` → the planned executor fallback applies
  (token dirs deny-read plus refusal while a known executor listens).

Findings that tighten the design without a ✅/❌ row:
- **Symlinks and socket paths** → everything goes under one root: [[2026-10-04-valetkey-root-dir]].
- **A settings `env` block reaches the broker** → [[2026-10-04-broker-environment-allowlist]].
- **New unfenced conditions:** `allowAllUnixSockets`, `allowAppleEvents`, extra `allowMachLookup`
  entries, a missing `allowedDomains`, and `PATH` set in a settings `env` block. Claude Code's own
  `git` calls run unsandboxed through `PATH`.
- **Shadowing is silent, and a shadowed broker never starts** → detection moves to the plugin
  hook and `doctor`.
- **Postgres:** six guard changes ([[2026-10-04-postgres-read-only-guards]]).

## Why
These are the consequences the table defined in advance. M0 confirmed most capabilities. Each miss
is either designed around without weakening the guarantee (approval, local store), or downgrades
exactly the affected source (`keyring` on macOS).

## Consequences
- M1 can start. The fence tests in CI reuse the spike's probe set (`spike/m0`).
- Still **UNTESTED**: user/local MCP scope, interactive elicitation UX, statusLine environment,
  subagent frontmatter hooks in a trusted folder, the write scope outside the project in a home
  dir, the Podman socket, Docker with a live daemon on Linux, gnome-keyring, the data-protection
  keychain on macOS. None of them is on the critical path; each is recorded on its integration
  page.
